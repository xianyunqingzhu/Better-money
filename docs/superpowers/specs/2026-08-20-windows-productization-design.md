# Better Money Windows 产品化设计

- 日期：2026-08-20
- 状态：已在对话中逐项确认，待书面复核
- 目标平台：Windows 10/11 64 位

## 1. 背景与目标

Better Money 当前以 FastAPI、SQLite 和原生网页前端构成，Windows 用户通过 `启动.bat` 运行。现有脚本要求目标电脑预装 Python，并在首次启动时联网创建虚拟环境、下载依赖；脚本还会在服务真正就绪前打开浏览器。这导致新用户首次点击快捷方式时经常无法使用，也使网络、Python 版本、环境变量和权限成为额外故障来源。

本次改造的目标是把项目产品化为普通 Windows 软件：用户从 GitHub Releases 下载一个安装包，选择安装位置，安装后双击快捷方式即可使用，不需要安装 Python，也不需要首次下载程序依赖。改造同时修复已确认的目标、总结和余额体验问题，并保证安装、升级和卸载过程不会意外损坏个人数据。

## 2. 范围

### 2.1 本期包含

- Windows 10/11 64 位安装包。
- 可选择程序安装目录。
- 独立无控制台启动器、单实例控制、服务就绪检查和浏览器打开。
- 程序文件与个人数据分离。
- 旧版 `data` 目录迁移、自动备份、手动备份与恢复。
- 多目标看板、目标金额可读性、目标删除修复和自动储蓄顺序分配。
- 周/月总结的任意日期区间、覆盖更新、重新生成和删除。
- 初始余额生效日期、自动月度结转和可追溯对账调整。
- 首次使用引导、AI 可选配置和统一错误反馈。
- 业务回归、安装、升级和干净系统验收测试。

### 2.2 本期不包含

- macOS 安装体验重做。
- Electron/Tauri 桌面窗口。
- 云同步、多用户账户或远程访问。
- 系统托盘图标。
- 自动更新。
- 代码签名证书采购。

现有 `.bat` 启动方式保留给开发者调试，但不再作为普通用户的入口。

## 3. 总体架构

安装包采用两层产物：PyInstaller 将 Python 解释器、FastAPI 服务、静态资源和依赖打成 Windows 应用目录；Inno Setup 将该目录、图标、快捷方式、卸载和升级规则制作成 `BetterMoney-Setup-<version>.exe`。

首版使用 PyInstaller 文件夹模式而非单文件模式，以减少每次启动的临时解包时间，并让静态资源定位和故障排查更稳定。

```text
GitHub Release
  └─ BetterMoney-Setup-<version>.exe
       ├─ 用户选择程序安装目录
       ├─ 安装程序文件
       ├─ 创建桌面快捷方式
       └─ 创建开始菜单快捷方式

快捷方式
  └─ BetterMoney.exe 启动器
       ├─ 检查现有实例
       ├─ 选择可用本地端口
       ├─ 启动 FastAPI 服务
       ├─ 轮询健康检查
       └─ 成功后打开默认浏览器
```

程序文件与个人数据严格分开：

```text
<用户选择的安装目录>\
  └─ 程序、静态资源和运行依赖（安装器管理）

%LOCALAPPDATA%\BetterMoney\
  ├─ data\
  │   ├─ better_money.db
  │   ├─ config.json
  │   └─ images\
  ├─ backups\
  ├─ logs\
  └─ runtime\
```

卸载默认只删除程序文件，保留 `%LOCALAPPDATA%\BetterMoney`。用户只有在卸载界面明确选择“同时删除个人数据”时才删除该目录。

## 4. 安装、启动与退出

### 4.1 安装

- 默认安装到 Windows 推荐的程序目录，允许用户改到其他磁盘或包含中文、空格的目录。
- 安装器创建桌面和开始菜单快捷方式。
- 覆盖安装前关闭正在运行的 Better Money。
- 升级不移动、不覆盖个人数据目录。
- README 将普通用户明确引导至 GitHub Releases 的 Setup 安装包，而不是 Source code ZIP。

### 4.2 启动器

启动器负责服务生命周期，不由批处理脚本承担。启动行为如下：

1. 获取当前 Windows 用户范围内的单实例锁。
2. 读取 `runtime` 中的上次实例信息，并调用健康接口验证产品标识和进程状态。
3. 已有有效实例时直接打开其浏览器地址。
4. 没有实例时优先尝试 `127.0.0.1:8642`；若被其他程序占用，则选择一个可用的仅本机端口。
5. 启动 FastAPI 服务，并将进程号、端口、随机会话令牌和版本写入运行时文件。
6. 轮询 `/api/health`，只有返回预期的 Better Money 产品标识和版本后才打开浏览器。
7. 启动超时或进程提前退出时，显示中文错误窗口，并提供日志位置。

运行时文件不包含 API Key。健康接口仅监听 `127.0.0.1`，不向局域网或公网开放。

### 4.3 重复点击与端口冲突

- 快速连续点击快捷方式不会创建多个服务进程。
- 已运行时再次点击只重新打开页面。
- 端口占用不会要求用户编辑配置文件。
- 不能仅以“端口可连接”判断实例，必须验证 Better Money 产品标识。

### 4.4 退出

关闭浏览器后后台服务继续运行。设置页提供“退出 Better Money”按钮，该按钮使用当前会话令牌请求仅本机可用的关闭接口。服务停止后页面显示“应用已退出，可以关闭此页面”。Windows 注销或关机时由系统终止进程。

安装器执行升级或卸载时，通过相同的实例识别机制请求退出；正常退出失败时再提示用户关闭程序。

## 5. 数据目录、迁移与备份

### 5.1 路径策略

开发模式继续允许使用仓库内的 `data`。安装版通过启动器传入或由配置模块解析 `%LOCALAPPDATA%\BetterMoney`，所有数据库、设置、图片、备份、日志和运行时文件均写入该用户目录。业务代码不得假设可写入安装目录。

### 5.2 首次启动

安装版在个人数据目录没有完成初始化标记时显示首次使用引导，提供：

- 全新开始。
- 从旧版 Better-money 项目或 `data` 目录迁移。
- 从 Better Money 备份恢复。

旧版迁移采用复制，不移动或修改用户选择的原目录。迁移流程先在临时目录验证数据库和配置，再原子替换新数据目录。成功页显示交易、目标和总结数量以及迁移前后计算余额。

若旧数据没有初始余额日期，以最早交易日期作为建议值；用户可在确认页修改。没有交易时默认使用迁移当天。

### 5.3 自动备份

- 每个自然日第一次成功启动时自动备份一次。
- 数据迁移、恢复、数据库架构升级和更正初始余额前额外备份。
- 默认保留最近 30 份自动备份。
- 自动备份包含数据库、架构/应用版本清单和去除 API Key 的非敏感设置。
- 备份写入临时文件，完成并验证后再改名为正式备份，避免中断产生看似有效的半文件。

### 5.4 手动导出与恢复

设置页提供：

- 立即备份。
- 恢复备份。
- 导出完整备份 ZIP。
- 导出全部交易 CSV。
- 打开数据文件夹。

完整备份 ZIP 包含数据库、非敏感设置和用户选择包含的图片。选择包含图片时提示截图可能含个人隐私。API Key 永不写入导出包。

恢复前自动创建当前状态备份；恢复文件必须通过格式、数据库完整性和版本兼容检查。恢复在临时目录完成，成功后原子切换；失败时保留当前数据并给出具体原因。

## 6. 目标功能

### 6.1 看板

当前只展示一个目标的圆环改为按优先级排列的多目标进度列表。看板展示所有状态为“冷静期”“进行中”“已暂停”的目标；已达成和已放弃目标保留在目标清单中，但不占用看板空间。

每个目标显示：

- 名称和状态。
- 已存金额、目标金额和剩余金额。
- 百分比和进度条。
- 第一优先级目标的“当前优先目标”标识。

目标很多时看板区域内部滚动，不能因为数量多而只显示第一个。暂停目标使用较弱的进度颜色，但文本保持清晰。

### 6.2 自动储蓄分配

收入的自动储蓄金额按活跃目标的优先级顺序分配：

1. 填充第一目标至目标金额。
2. 剩余金额继续填充下一目标。
3. 已存满、已暂停、已达成和已放弃目标不接收自动分配。
4. 所有可分配目标存满后，剩余金额不分配。

存满不等于已经消费。只有用户确认“达成并购买”时才写入真实支出。

### 6.3 删除

前端删除按钮调用 `DELETE /api/goals/{id}`，不再把 `delete` 作为目标动作发送。删除前显示目标名称、状态和已存金额，并说明目标金额只是规划：删除目标不会改变账本余额，也不会删除任何收入、支出或对账记录。

删除已达成目标不会删除此前因购买产生的交易。删除后同时刷新目标清单和看板。不存在的目标返回明确的 404 提示。

## 7. 总结功能

### 7.1 生成窗口

原有两个固定按钮合并为“生成总结”窗口，包含：

- 总结风格：周总结、月总结。
- 快捷区间：本周、上周、本月、上月。
- 自定义开始日期和结束日期。

周/月定义写作风格和分析深度，不强制区间必须恰好是一周或一个自然月。开始日期不得晚于结束日期，自定义区间最长 366 天。周总结目标篇幅为 200～400 字，月总结为 400～800 字。

### 7.2 存储与重复生成

总结唯一业务键为“总结风格 + 开始日期 + 结束日期”。相同组合再次生成时，前端提示是否覆盖；确认后更新原记录，不产生重复卡片。不同风格或区间保存为新记录。

账目在某总结区间内新增、修改或删除时，该总结标记为过期。过期卡片提供“按原区间重新生成”。

### 7.3 删除

增加总结删除接口和前端删除按钮。删除前二次确认；删除只影响总结正文和该总结专属的配图，不影响账单、目标或对账记录。配图文件删除失败时记录错误并返回可理解的结果，不能把数据库成功和文件清理失败伪装成完全成功。

AI 不可用时不保存空总结；界面保留刚才的风格和日期选择，用户修复配置后可以直接重试。

## 8. 初始余额与对账

### 8.1 定义

初始余额定义为“开始记账日期当天第一笔记录发生前的全部资金”。新增 `initial_balance_date` 设置。余额只累计该日期及之后的交易和调整：

```text
当前账本余额
= 初始余额
+ 生效日期以来的收入和退款
- 生效日期以来的支出、转账、取现和还款
+ 生效日期以来的对账调整
```

### 8.2 月度结转

用户不需要每月重填初始余额。系统根据初始余额和历史流水自动计算每月期初余额、本月收入、本月支出、本月调整和期末余额。

### 8.3 更正初始余额

首次设置后，初始余额和日期默认只读。用户点击“更正初始余额”后，界面说明该操作会影响全部后续月份；确认时先自动备份，再保存新值。普通对账差异不得通过修改初始余额解决。

### 8.4 对账调整

对账继续以独立调整记录保存。设置页展示调整历史，包括日期、差额、原因和创建时间。错误调整通过“撤销”生成金额相反并关联原记录的新调整，不做无痕硬删除。

目标的已存金额属于资金规划，不再次从账本总余额扣除。界面分别显示账本总余额、已规划给活跃目标的金额和尚未规划的余额。

## 9. 首次引导与 AI 配置

首次引导依次完成：

1. 全新开始、迁移或恢复选择。
2. 开始记账日期和初始余额。
3. 月预算和收入自动储蓄比例。
4. 可选的 AI 服务配置。

未配置 AI 时，手动记账、目标、图表、余额和备份必须正常使用。智能文字记账、图片识别和 AI 总结显示可操作的配置提示，不阻止进入应用。

AI 普通设置显示服务商和 API Key，并提供“测试连接”；API Base 和模型名称放在高级设置。API Key 仅保存在本机配置文件中，不写入日志、运行时文件或导出备份。

## 10. 界面与错误反馈

- 正文默认 15px。
- 辅助文字不低于 13px。
- 目标金额至少 14px，关键金额使用 15～16px及较粗字重。
- 提高弱色文字的对比度，不只依赖颜色表达状态。
- 在 Windows 100%、125%和150%缩放下验证布局。
- 窄窗口下按钮、日期选择和目标操作不能被遮挡。
- 普通成功操作使用短暂状态提示。
- 删除、覆盖和重大余额更正使用确认对话框。
- 保存期间禁用触发按钮，防止重复提交。
- 后端错误返回稳定错误码和用户可理解的中文消息。
- 启动日志和业务日志分开保存，并对 API Key、授权头和会话令牌脱敏。

## 11. 数据库与兼容性变化

实施时需要可重复、带版本号的数据库迁移机制。至少包含：

- 总结表支持“风格 + 开始日期 + 结束日期”唯一约束或等价的应用层约束。
- 调整记录增加撤销关联字段，以追溯原调整。
- 配置增加 `initial_balance_date`、首次引导完成标记和应用版本信息。
- 数据库记录架构版本，迁移前自动备份。

现有数据库必须原地升级且保留全部记录。开发和测试环境也必须走同一迁移入口，不能仅依赖全新建表。

## 12. 安全与隐私

- 服务只绑定 `127.0.0.1`。
- 退出等控制接口使用每次启动生成的会话令牌。
- 健康检查不返回敏感配置。
- 上传文件继续限制类型和大小，并使用应用生成的文件名。
- 日志、自动备份和导出包不包含 API Key。
- 完整备份包含图片前明确提示隐私风险。
- 卸载删除个人数据必须由用户明确选择并再次确认。

## 13. 测试策略

### 13.1 自动测试

测试使用临时数据目录和临时数据库，不得写入开发者真实 `data`。覆盖：

- 目标删除前后端契约。
- 多个活跃目标的展示数据和排序。
- 自动储蓄跨目标分配、不超额和暂停目标跳过。
- 总结自定义区间、重复覆盖、过期、重新生成和删除。
- 初始余额生效日期、跨月期初/期末和调整撤销。
- 旧版数据迁移、自动备份、完整导出、成功恢复和失败回滚。
- 启动健康检查、产品标识、单实例和端口冲突。

### 13.2 安装与升级测试

- 默认安装目录和用户选择目录。
- D盘、中文路径和含空格路径。
- 覆盖安装保留数据。
- 卸载默认保留数据。
- 用户明确选择时删除个人数据。
- 旧版仓库 `data` 迁移。

### 13.3 干净系统验收

在未安装 Python 的 Windows 10/11 64 位环境验证：

- 第一次点击快捷方式即可打开。
- 连续点击不创建重复服务。
- 端口冲突可自动恢复。
- 无网络时手动记账正常。
- 多目标全部显示且金额清晰。
- 目标和总结可以正确删除。
- 总结可选择日期区间。
- 初始余额自动跨月延续。
- 备份能够真实恢复。
- 覆盖安装不丢数据。
- 100%、125%和150%显示缩放均可操作。

## 14. 发布方式

首版发布 Windows 10/11 64 位安装包：

```text
BetterMoney-Setup-1.0.0.exe
SHA256SUMS.txt
Release Notes
```

版本号在应用、健康接口、安装器和发布文件名中保持一致。构建由仓库中的可重复脚本完成，构建产物不提交到 Git，只上传到 GitHub Release。

未签名测试版可能触发 Windows SmartScreen。早期测试接受该提示；正式扩大分发前再评估代码签名。

## 15. 实施顺序

1. 建立隔离测试数据目录和数据库迁移机制。
2. 修复目标、总结和余额业务规则，并补齐回归测试。
3. 完成首次引导、可读性和错误反馈调整。
4. 将安装版数据路径迁移到 `%LOCALAPPDATA%`，实现迁移、备份和恢复。
5. 实现 Windows 启动器、单实例、健康检查和安全退出。
6. 建立 PyInstaller 与 Inno Setup 构建流程。
7. 执行安装、升级和干净系统验收。
8. 更新 README、使用说明和 GitHub Release 指引。

## 16. 完成标准

只有以下条件全部满足，才视为本次产品化完成：

- 普通用户无需 Python 即可安装和首次启动。
- 启动、重复点击、端口冲突和退出行为符合本设计。
- 安装位置可选，个人数据位置固定且受保护。
- 现有用户可无损迁移，备份与恢复经过实际验证。
- 已确认的目标、总结和余额问题全部修复并有自动测试。
- 安装、覆盖升级和卸载规则经过 Windows 10/11 验收。
- 文档明确区分普通用户安装包与开发者源代码启动方式。
